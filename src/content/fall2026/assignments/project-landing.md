# Landing page · One clear invitation

**Project 4 · 100 points · Due December 2, 2026 at 11:59 p.m. Pacific**

## Studio brief

Create a single landing page that helps one audience understand an offering and take one useful action. Choose a workshop, publication, event, creative tool, or service concept. If invented, identify it as a class concept. Use truthful content and a real link destination rather than simulated customers or unsupported promises.

## Build sequence

Use the [landing starter ZIP](/fall-2026/starters/landing.zip) in the existing repository's `landing/` folder. This project concludes December 2 so that final preparation can focus on curation.

1. Define the reader, offering, and main action in one sentence each. Keep the scope small enough for one page.
2. Create two Figma frames, 375px and 1280px, with real content. Include a compact style tile and one default/focus action appearance. Use the November 16 critique to revise one confusing decision. Do not create a separate brand manual.
3. Build one HTML structure containing a header, navigation where useful, a main hero/introduction, three concise benefits or features, a details section, a main action, and footer/credits. A useful action can link to on-page details or a credible external destination.
4. Translate the two frames into one flexible document. Use Grid/Flexbox, consistent spacing/type, and at least one purposeful responsive rule. Test between the design widths instead of creating separate duplicate mobile/desktop content.
5. Give the action useful text and a visible keyboard focus appearance. Use an anchor for navigation and a native button for a real action. A live form backend, purchases, newsletter collection, and API integration are outside the core.
6. If experimenting with a form, use visible labels and accurately state that it is a local prototype when no data is sent. Never fake successful registration. Motion is optional; honor reduced motion if you add it.
7. Run the November 30 test clinic, repair core faults, verify the published URL, and add the landing page to the existing portfolio. Complete delivery on December 2 before beginning final curation.

## Source check

Point to the CSS that adapts one content group and explain the relationship to the Figma frames. Reach and activate the main action with the keyboard, then name its element and actual destination/behavior. Independently change one relevant property or piece of content and verify it.

**AI allowance:** scoped assistance is optional only after the required checks. Set a specific small task, inspect returned code, change it yourself, and test the actual behavior. Do not generate a whole finished page and treat inspection as optional. Disclose retained help in your existing source notes. No paid tool is required.

## Studio evidence

Submit the live landing URL, repository link, and viewable Figma file or exported frames. Add four to six sentences explaining the reader/action, one responsive adaptation, one tested repair, and source/AI assistance. This is one project grade; the planning and coding are not separate project grades.
