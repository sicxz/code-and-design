# Recipe · Structure and style

**Project 1 · 100 points · Due October 7, 2026 at 11:59 p.m. Pacific**

## Studio brief

Build a single recipe page that someone can read and follow. This first project joins meaningful HTML with deliberate CSS. Use a recipe you know or adapt one with credit; choose modest content so you have time to understand every element and rule.

**Student AI is off for the entire project.** Use class demonstrations, reference documentation, and human help. Your source check is individual.

## Build sequence

Start with the [recipe starter ZIP](/fall-2026/starters/recipe.zip), or save its [HTML](/fall-2026/starters/recipe/index.html), [CSS](/fall-2026/starters/recipe/styles.css), and [instructions](/fall-2026/starters/recipe/README.md). The starter is deliberately unfinished. Use the [workspace guide](/1/resources/workflow/) to move its body markup into CodePen if that is your editor.

1. Write an informative title, a two-to-three-sentence introduction, ingredient list, and ordered method. Use as many ingredients and steps as the recipe actually needs; do not pad either to meet a quota.
2. Mark up a clear `header`, `main`, and `footer`, with one `h1`, logical `h2` section headings, paragraphs, `ul`, `ol`, and properly nested `li` elements.
3. Add one relevant image you own or may reuse. Include suitable alternative text and a visible credit or note that you made it. Add a descriptive link to your recipe/content source when applicable.
4. Style the page with selectors you understand. Establish a readable title/body hierarchy, comfortable line height, a limited reading width, and intentional margin and padding. One font family is sufficient.
5. Test at a narrow width and a wide width. The recipe must remain readable; images must fit. A media query is not required if the simple layout already adapts.
6. Use a partner reading and the October 7 source check to repair the core. Save your final Pen or local document, then keep it for the manual repository migration in week 3.

## Source check

On October 7, independently identify a relevant element/rule, predict an instructor-selected spacing or type change, make it, and explain its result. Repair one small nesting or class-name fault. If an action needs recovery, complete the smaller exercise and another attempt described in [Source checks](/1/resources/source-checks/). The check contributes to the 20-point understanding criterion below.

## Studio evidence

Submit one saved CodePen URL, or the HTML/CSS and image files if online access is blocked. Add three to five sentences: name one structural decision, one CSS decision, and a source/reference credit. You may point to existing source notes rather than copy them. No separate essay or design file is required.

## Delivery check and rubric

| Criterion | Points | What to show |
| --- | --- | --- |
| Meaningful HTML and accurate recipe content | 30 | Heading hierarchy, correct lists/nesting, usable instructions, and a sensible page order. |
| Readable CSS | 25 | Explained selectors, type hierarchy, intentional spacing, and a page that fits narrow/wide screens. |
| Source understanding | 20 | Identify, predict, edit, and explain the relevant code independently. |
| Image, links, and credits | 15 | Image fits and has useful alt text/credit; source links work. |
| Delivery and concise explanation | 10 | Saved artifact opens and the required decisions are stated clearly. |

Use the shared [performance levels](/1/resources/rubrics/). Optional exploration: a small color or typographic detail that supports the recipe. No animation, multiple pages, custom icons, or elaborate brand system is required. The final portfolio will link to this work without re-grading it.
