# Field guide · A responsive collection

**Project 3 · 100 points · Due November 15, 2026 at 11:59 p.m. Pacific**

## Studio brief

Help a reader recognize or choose among **three related entries**. The subject might be native plants, typefaces, print processes, places, tools, or another collection you can describe accurately. Use a repeated structure so readers can compare. Responsive layout and reliable navigation matter more than the number of decorations.

## Build sequence

Download the [field guide starter](/fall-2026/starters/field-guide.zip) and put it in `field-guide/` in the same portfolio repository.

1. Define the reader and task in two sentences. Choose three entries and two-to-three shared information fields, such as “recognize it,” “use it for,” and “watch for.” Write real, verified content and keep source links.
2. Sketch one entry and its narrow/wide arrangement. Figma or paper is acceptable here; reuse the type/color/spacing habits from the tribute instead of producing a large new design packet.
3. Write a header/introduction, a navigation list linking to each entry, a `main` with three semantic `article` sections, and a footer with source/home links. Each article needs a heading and its actual shared fields. Use a meaningful list where the content calls for one.
4. Build one article fully before repeating its pattern. Use shared classes and a Grid or Flexbox layout. Let long text wrap; do not hard-code heights that clip different entries.
5. Use a media query to adapt the arrangement based on your content. Test 375px, an intermediate width, around your breakpoint, and a wide width. A fixed sidebar is optional, not a requirement.
6. Add suitable images only where they help the guide. Every used image needs appropriate alternative text and a credit. Decorative images are optional; no fake code snippets or positional decoration quotas.
7. Add a skip link to the main content, visible keyboard focus, matching navigation IDs, and a working route home. Use the November 9 debugging clinic to verify one substantive repair.

## Source check

Explain the reusable card class, the layout container, and the rule that changes at the breakpoint. Demonstrate one working anchor destination and one bug diagnosis. The November 2 independent construction/debugging check contributes to source understanding; arrange recovery and another attempt when needed.

**AI allowance:** optional scoped generation is available only after both source checks. Limit it to one small understood section or rule; inspect, modify, and verify every retained line. You may complete the entire project without AI. Disclose actual assistance briefly in the existing source notes.
