# Week 8 · Design a clear invitation

**Monday, November 16 and Wednesday, November 18 · 1–3:30 p.m.**  
Independent work estimate: **6 hours total**, including the landing page. Scoped AI help is optional only after the required checks; design decisions and source explanations remain yours.

## Studio brief

Build a small landing page for an invented or real offering: a workshop, local event, publication, creative tool, or service concept. One reader should understand what it is, why it matters to them, and what useful step to take. Read the [landing page brief](/1/assignments/project-landing/) before choosing content.

## Build sequence

Each studio: reconnect 1:00–1:15; demonstrate 1:15–1:40; guided work 1:40–2:10; break 2:10–2:20; project build 2:20–3:05; critique/source check 3:05–3:25; save 3:25–3:30.

**Monday: audience and a focused Figma plan.**

1. Write one sentence each for the reader, the offering, and the action. Avoid unsupported claims or testimonials from invented customers. Label a fictional offering as a class concept.
2. Choose concise content for a hero, three benefits or features, a details section, and a clear action linking to a real destination. An anchor to on-page details is sufficient and requires no backend.
3. In your existing Figma file or a small new project file, create a 375px frame and a 1280px frame. Reuse the content in both. Learn auto layout only for one repeated component or row that helps this design.
4. Make a compact style tile: type choice, text/background/accent colors, spacing, and link/control appearance. Draw the main action's focus appearance along with its default state.
5. Pair critique: the reviewer has 20 seconds to identify the offering and next step. Record one revision, then make it. Two short sentences are enough.

**Wednesday: two frames, one document.**

1. Download the [landing starter](/fall-2026/starters/landing.zip) into `landing/` in the same repository. Write meaningful HTML for the agreed content before styling.
2. Keep one logical source order. Do not duplicate all content into separate “mobile” and “desktop” HTML versions.
3. Build the narrow layout first, then adapt the feature group or hero with Grid/Flexbox when the content needs more space. Test a width between the frames.
4. Add a real action such as `<a class="action" href="#details">See workshop details</a>` and an exactly matching details section ID. If linking off-site, use a trustworthy real destination and describe it accurately.
5. Compare the browser with your frames. Preserve hierarchy, spacing relationships, and the action's prominence. Document one deliberate adaptation when flexible behavior requires a different arrangement.

## Source check

Which HTML appears in both the narrow and wide layout? Point to the CSS that changes its arrangement. Explain why a link is appropriate for the main action. If it actually performs an action without navigation, what native control would be more appropriate?

## Studio evidence

Submit [Landing page direction](/1/assignments/practice-08/) with one Figma link or exported image, a brief source translation plan, and one question. It is the weekly planning/source exercise; the finished landing page is assessed December 2.

## Delivery check

Check the concept's truthfulness, a real destination for the action, a complete content outline, and two useful layout frames. The form/interaction practice next week does not require a live signup service. Optional motion or extra sections should not displace the core reading task.
